# Техническое задание: Информационная система «Военкомат»
## Контекст: Лабораторный практикум по БД (Часть 2)

### 1. Общие технологические требования
- **Backend**: Python (FastAPI). Взаимодействие с БД строго через библиотеку `psycopg2` (обертка над `libpq`).
- **Frontend**: C++ (Qt 6.10). 
- **Архитектура**: Клиент-серверная (HTTP JSON API).
- **Стиль UI**: Классический статический (стандарт CUA - Common User Access).

## Лабораторная работа №2: Пользовательский интерфейс
**Статус: В процессе (40%)**

### Технические требования (Стандарт CUA):
- **Управление**: Основное управление — клавиатурные события.
- **Логика работы с таблицами**:
  - Выбор активной таблицы осуществляется через меню `Tables` (`Alt+T`).
  - Все операции (`Ctrl+A`, `Ctrl+V` и др.) применяются строго к выбранной активной таблице.
- **Трансляция событий**: Все события указателя (мыши) транслируются в клавиатурные события и обрабатываются ими (например, клик по "OK" генерирует `Qt::Key_Enter`).
- **Горячие клавиши (ОБЯЗАТЕЛЬНО)**:
  - `Ctrl+A`: Добавление записи в активную таблицу.
  - `Ctrl+V`: Просмотр данных активной таблицы.
  - `Ctrl+D`: Удаление записи из активной таблицы (отдельное окно ввода ID).
  - `Ctrl+U`: Обновление (Update) записи в активной таблице.
  - `Ctrl+Q`: Выполнение специального запроса (выбор из списка).
  - `Ctrl+S`: Сохранение результата последнего запроса (уведомление с путем к файлу на сервере).
  - `Ctrl+B`: Создание бэкапа БД (запрос пароля суперпользователя).
  - `Ctrl+E`: Выход из приложения.
- **Интерфейс меню**:
  - Активация главного меню: клавиша `F10`.
  - Навигация: `Alt` + подчеркнутая буква в названии.
  - Первое меню — `File` (содержит команду выхода).
- **Навигация в формах**:
  - Между полями: `Tab` (вперед), `Shift+Tab` (назад).
  - Внутри полей: Клавиши управления курсором (стрелки).
  - Подтверждение: `Enter` (кнопка "OK"), Сброс: `Esc` (кнопка "Cancel").
- **Принципы UI**:
  - **Статичность**: Все окна и меню статические. Отказ от прогрессивного предложения действий.
  - **Запрет скролла**: Информация в диалоговых окнах типа «Форма» не скроллируется. Размер окна фиксирован.
  - **Транзакционность**: Без явного подтверждения ("OK") данные на сервер не отправляются.
  - **Отклик**: Время отклика интерфейса на событие не более **0,1 с**.
  - **Эргономика**: Здоровье оператора (черный текст на светлом фоне) важнее эстетики.

## Лабораторная работа №3: NoSQL База данных (BerkeleyDB)
**Статус: Ожидание реализации**

### Основные требования:
- [ ] **BerkeleyDB**: Для каждой таблицы PostgreSQL создается соответствующая БД BerkeleyDB.
- [ ] **Конвертор**: Консольное приложение на Python для автоматической миграции.
- [ ] **Формат хранения**:
    - **Ключ (Key)**: Первичный ключ из PostgreSQL. Для M2M таблиц: `{id1}_{id2}`.
    - **Значение (Value)**: Сериализованные значения столбцов в формате **JSON**.
- [ ] **Алгоритм**: Динамическое получение имен таблиц и столбцов через `information_schema`.
- [ ] **Верификация**: Проверка корректности данных через утилиту `db_dump`.
