# План миграции сервера Voenkomat: Python (FastAPI) -> C++ (Qt 6.10)

## 1. Цели
*   Полная замена текущего сервера на Python (`main.py`) эквивалентом на C++ с использованием Qt.
*   Сохранение совместимости API для текущего клиента.
*   Минимизация зависимостей (использование встроенных модулей Qt).

## 2. Стек технологий
*   **Язык:** C++17/20
*   **Framework:** Qt 6.10.0 (MinGW 64-bit)
*   **Модули:**
    *   `QtHttpServer`: Обработка REST запросов.
    *   `QtSql`: Драйвер QPSQL для связи с PostgreSQL.
    *   `QtCore`: JSON (QJsonDocument), логирование, работа с конфигами (QSettings).

## 3. Архитектура приложения
Проект будет разбит на следующие классы/компоненты:
1.  **`DatabaseManager`**: Singleton для управления пулом соединений с БД, выполнением запросов и конвертацией `QSqlQuery` в `QJsonArray`.
2.  **`RestServer`**: Обертка над `QHttpServer`, определяющая маршруты (routes) и вызывающая методы БД.
3.  **`AuthService`**: Простая логика проверки `SUPERUSER_PASSWORD` (из хедера `x-auth-token`).
4.  **`MigrationTools`**: Логика для создания бекапов в JSON и конвертации в NoSQL (аналог `converter.py`).

## 4. Этапы реализации

### Этап 1: Подготовка проекта (День 1)
*   Создание нового подпроекта в `voenkomat_app.pro` (или отдельного `.pro` файла для сервера).
*   Настройка зависимостей (`network`, `httpserver`, `sql`).
*   Реализация `ConfigReader` для чтения `config.ini`.

### Этап 2: Слой базы данных (День 2)
*   Инициализация `QSqlDatabase` (PostgreSQL).
*   Написание универсального метода `executeSelect(QString sql, QVariantList params)` возвращающего `QJsonArray`.
*   Написание метода `executeInsertUpdate(QString sql, QVariantList params)` для CRUD.

### Этап 3: Реализация API Эндпоинтов (День 3-4)
*   `GET /api/all-tables`: Список таблиц.
*   `GET /api/{table}`: Получение данных с фильтрацией.
*   `POST /api/{table}`: Добавление записи (с учетом прав доступа).
*   `PUT /api/{table}/{id}`: Обновление.
*   `DELETE /api/{table}/{id}`: Удаление.
*   `POST /api/execute-query`: Произвольный SQL для админа.

### Этап 4: Бизнес-логика и Доп. функции (День 5)
*   Перенос логики `sync_bidirectional_links` (связи призывников).
*   Реализация эндпоинта `/api/backup` (генерация JSON файла через Qt).
*   Реализация NoSQL конвертера (используя SQLite или файловую структуру, если `dbm` недоступен).

## 5. Ожидаемые сложности
*   **Драйвер QPSQL:** Нужно убедиться, что `qsqlpsql.dll` видит библиотеки PostgreSQL (`libpq.dll`).
*   **CORS:** В `QHttpServer` нужно будет вручную добавлять заголовки `Access-Control-Allow-Origin: *`.
*   **Динамические типы:** В Python `psycopg2` сам определяет типы. В Qt нужно будет проверять типы колонок через `QSqlRecord`.

## 6. Чек-лист проверки
- [ ] Сервер запускается на порту 8000.
- [ ] Таблицы успешно читаются из Postgres.
- [ ] Приложение-клиент подключается без ошибок CORS.
- [ ] Запросы на изменение данных требуют "admin" токен.
