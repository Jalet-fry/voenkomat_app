# Спецификация требований к лабораторным работам №7-9 (на базе №1-3)

Данный документ объединяет требования к серверной части (Backend), пользовательскому интерфейсу (Frontend) и NoSQL составляющей, адаптированные под текущий стек технологий (Qt C++, Python, PostgreSQL, BerkeleyDB).

## 1. Серверная часть (Backend) — ЛР №7 (на базе №1)

### Общие требования:
- **Архитектура:** RESTful HTTP-сервер.
- **Формат данных:** JSON (в запросах и ответах).
- **БД:** PostgreSQL, взаимодействие через `libpq` (в C++ версии) или `psycopg2` (в Python версии).

### Ролевая модель:
- **Пользователь:** Просмотр, фильтрация, редактирование данных (кроме справочников).
- **Суперпользователь (admin):** Полный доступ, включая редактирование справочников (`LOOKUP_TABLES`) и создание бэкапов. Авторизация по паролю через заголовок `X-Auth-Token`.

### Ресурсы (Endpoints):
- `GET /api/{table}` — получение списка записей (с поддержкой фильтрации через query param `filters`).
- `POST /api/{table}` — создание новой записи.
- `PUT /api/{table}/{id}` — обновление существующей записи.
- `DELETE /api/{table}/{id}` — удаление записи.
- `POST /api/execute-query` — выполнение предустановленных SQL-запросов (ЛР 5-6).
- `POST /api/backup` — создание JSON/SQL бэкапа всей базы.

### Справочники (LookUp Tables):
- `fitness_categories`
- `commissioners`

## 2. Пользовательский интерфейс (Frontend) — ЛР №8 (на базе №2)

### Основные принципы:
- **Классический UI:** Статические окна, отсутствие скроллинга в формах.
- **Управление:** Полная поддержка клавиатуры (горячие клавиши) по стандарту CUA.
- **Транзакционность:** Подтверждение действий (ОК/Cancel).
- **Скорость:** Отклик интерфейса не более 0,1 сек.

### Горячие клавиши:
- `Ctrl+A`: Добавить запись.
- `Ctrl+V`: Просмотреть таблицу.
- `Ctrl+D`: Удалить запись.
- `Ctrl+U`: Обновить запись.
- `Ctrl+Q`: Окно специальных запросов.
- `Ctrl+S`: Сохранить результат запроса (в .xlsx).
- `Ctrl+B`: Создать бэкап (требует пароль админа).
- `F10` или `Alt`: Вызов меню.

### Функционал:
- Просмотр любой таблицы из списка.
- Фильтрация данных по выбранному полю.
- Экспорт результатов запросов и всей БД в формат `.xlsx` (QXlsx).

## 3. Конвертер и NoSQL — ЛР №9 (на базе №3)

### Требования к конвертеру:
- **Тип:** Консольное приложение.
- **Источник:** PostgreSQL.
- **Назначение:** BerkeleyDB (Ключ-Значение).
- **Формат хранения:**
    - Ключ: Первичный ключ (PK) из Postgres.
    - Значение: JSON-строка со всеми остальными полями записи.

### Алгоритм работы:
1. Подключение к PG.
2. Итерация по всем таблицам схемы `public`.
3. Сериализация каждой строки в JSON.
4. Запись в соответствующий `.db` файл BerkeleyDB.
